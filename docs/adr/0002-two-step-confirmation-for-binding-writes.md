# Two-step confirmation token for legally binding mutations

RS.ge write transitions (`send_waybill`, `close_waybill`, `confirm_waybill`, `reject_waybill`, `ref_waybill` / `cancel_waybill`, `del_waybill` / `delete_waybill_draft`, `save_invoice` / `create_waybill_invoice`) carry real legal and tax consequences, and MCP clients vary in how strictly they enforce tool annotations. We enforce a server-side two-step confirmation flow on every legally binding or destructive write: the first call returns a Georgian/English summary of the exact action and an in-memory confirmation token that is single-use, expires after 5 minutes, and is bound to the exact tool name and canonical hash of the arguments; the actual SOAP mutation executes only when that token is passed back after user approval, alongside standard MCP `readOnlyHint`/`destructiveHint` annotations. Creating or updating an unactivated draft (`save_waybill_draft`) is exempt and executes directly.
